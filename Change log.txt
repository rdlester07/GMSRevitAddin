v2.0

Cleaned up extract pieces process to totally ignore legacy code for units collection. (commented out with notes to assist in readding in the future if needed)

Added config file creation to store parts manager location per project and any future project based variables instead of hardcoded parts manager name located in the project path. Creates a hidden "GMS config" folder in the project folder containing the Revit model (ie. J:\000 - Project Name\2 - Main\RM - RevitModel\) then creates the "GMS.config" file in this new folder. The config file is set to hidden and readonly. Readonly must be removed before you can delete the file programmatically.

Converted piece extraction process to use parts manager location from latest saved config file.

Added check in piece extraction to look for any blank values (ie. same detail number, same origin letter but 2 different sheets will combine on the schedule and have a blank value for sheet). If any value is blank, throws a warning displaying all available info for the tag and skips over adding that line to the parts manager.

Added settings form, moved suppress type parameter warning to settings form.

Changed icon and text for show/hide tags so that the image is more visible and the image and text change in relation to the parameter value.

Added feature for when duplicating a drafting view, whether or not the original view and/or the duplicated view is opened.

v2.1.2

Corrected DuplicateViews to fix unexpected behavior. Previous version, if a view was activated on a sheet, after closing both original and new duplicated view, current view was set to the activated view itself and not the sheet the view is on. In other words, it would open the view instead of returning to the sheet the view was on. New version stores last ViewActivated, which triggers when opening a view or a sheet but does not trigger when activating a viewport on a sheet. 

Update NotAReference to also change "Work Points - Unit" lines to strong reference (13) and "Work Points - Module" lines to weak reference (14).

v2.4

Added UnitInfo tool for updating unit build/bunk/statuses. This tool was disabled in favor of two seperate tools specifically to update unit build number and unit bunk number.

Revised how keyboardshortcuts are handled. Previously the xml file was converted to a string and then parsed and modified as neccesary then saved over original file. This method did not always work correctly. New UpdateKeyboardShorcuts.cs adds/modifies directly to the xml file using xDocument. 

Updated CreateUnitSheet. Previously, FEC collected all BuiltInCategory.OST_TitleBlocks then filtered out types to leave only instances. If this was the first unit sheet created, it would crash because there is no instance yet. Changed to collect only types, not instances. Then pull the type ID for use in creating the new sheet.

Revised CreateUnitSheet to check if schedule name exists prior to attempting to create the schedule. If unit sheet was deleted, the schedule will remain behind unless manually deleted. This caused errors when making a new unit the same number as a deleted unit. Now, if schedule name exists, dialog pops up with options to overwrite existing schedule (delete existing then create new), use existing, or cancel.

Updated SettingsForm>Create config file. When project is moved to Archive folder, model retains original GetWorksharingCentralModelPath(). This caused creation of project folder structure and config file in the Projects folder even though the model was in the Archive folder. Also, when opening out-of-house models, this would either create an unneeded config file or error out. Updated method now checks if Directory.Exists(projectRevitFolder) {fixes issue with incorrect workshare model path in moved project} and projectRevitFolder.Contains(@"Main\RM - RevitModel") {only creates config file for models in the main phase/revit model folder. Any other folder structure will be ignored}.

Added Unit Release Date tool to batch update released dates on unit sheets.

Changed Show/Hide tags. Previously, Labels and linework in the GIT - Piece Tag had thier visibility set to a global parameter which this function toggled on/off. However, the tag is still in the view and still selectable even though it is invisible. This version changes how show/hide tags are handled. Global variable still exists for the purpose of toggling the button graphics but this function now hides the tags in all elevation views instead of turning the linework invisible. Progress bar added as well.

Progress bar feature added to help display that the program is processing and not hung.

Added progress bar to ManualUpdateOrigins and ExportPars. 

***Note: not too pleased with how this progress bar works. Because the fill is an animation, bar never will show 100% as the animation is halted while processes are performed. Tried using different step increments, tried making pBar.Max 100 and using percentages for increments, tried forcing progressbar.Value = progressbar.Maximum... None worked. Need to improve this progress bar in the future. 

Improved ManualUpdateOrigins, UpdateOrigins, and OriginLetterUpdate to only set parameter value if != value to set. Previous versions overwrote parameter value no matter what it was. This change should help to reduce the number of non-editable object/workset warnings. 

Unit SCHEDULE and piece schedule creation moved to ExportParts.

Export Parts changed to no longer update tags prior to exporting. Will check for discrepancies and error out if any found.

OriginLetterUpdater has been changed to look for C:\GMS\Revit\2019\Addins\PieceDescriptions.txt to populate defDictionary. Defaults to the hard coded list if !File.Exists or error in loading.

Creation of unit schedule for piece extraction had an issue. Apparently because we create the Origin, Origin Letter and Origin Sheet parameters as shared parameters and convert to project parameters in code, it leaves remnants in the database. Pulling a list of SchedulableFields of a Curtainwall Panel found 3 SchedulableFields with the same name for Origin and Origin Sheet (did not search for origin letter as this is not on a schedule create through code). Previous code just took the first instance of a SchedulableField that matched the name querried...which may or may not be the parameter that is actually schedulable. This would leave the cells blank in the schedule as the field is looking at the wrong parameter. New method saves the parameter.Id as the code is checking for discrepencies. Then, during schedule creation, it searches for a SchedulableField where Field.ParameterId == parameter.Id stored earlier.

Added to the OnViewActivated for a Unit drawing so that when a Unit drawing is opened it will verify that the schedule name and schedule filter match the sheet name. If not, it corrects them. I also added this to the ViewNames.SheetWatcherUpdater to check/correct these if the sheet name is changed. Note that doing this caused serveral issues caused by the detailWatcherUpdater firing during this change. I attempted to disable the detailWatcherUpdater and re-enable after update (no change in behavior), unregister detailWatcherUpdater and re-register after update (errors out. method is not allowed during execution of a dynamic update) and finally just removed error message reporting from the catch statement in the detailWatcherUpdater letting it die silently instead of crashing. This lets the SheetWatcherUpdater complete without any futher issues, though this isn't the best solution to the problem. Needs more research into how to make this work properly without disabling the error message for the detailWatcherUpdater.
